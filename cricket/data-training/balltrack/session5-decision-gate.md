## Per-field eff-score formula

All eff-scores use the formula from [`validate_balltrack.py`](../../../validate_balltrack.py):

```
raw_score_f(ball) = max(0, 1 - |pred_f - gt_f| / tol_f)        # linear decay, clipped [0,1]
contrib_f(ball)   = (w_f / sum_{f' in available} w_f') * raw_score_f(ball)   # renorm per ball
eff_score(field)  = mean_ball( contrib_f ) / w_f * 100           # normalise back by weight
```

Tolerances (OLD approx): kph=3, bounce_x=0.25, stump_y/z=0.12, release_y/z=0.15,
bounce_y=0.15, impact_x=0.25, impact_y/z=0.15, swing_angle/deviation=2.0 deg.

Weights: bounce_x/kph/stump_y/stump_z/impact_x=0.10; deviation/swing_angle/release_y/release_z/impact_y=0.08; bounce_y/impact_z=0.05.

**Overall recommendation: for all 12 scored fields, keep the current baseline
(flat median for most fields; V2 constants for kph and stump_z where they lead).
Physics-fallback mode scores 14.79% overall vs 26.23% for flat median on this 115-clip
VAL sample — a 11.4 pp regression. Root cause: homography calibration fails on most
clips (hom.valid=False), so the tracker uses fallback pixel scales that are incorrect
for clips whose resolution differs from the hand-calibrated clips. Physics is disabled
in production (CRICKET_PREDICTOR_MODE=auto resolves to constants when hom.valid=False).
Session 5 confirms this is the correct policy.**
